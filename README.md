# Лоты — учёт вложений

PWA на русском языке для учёта вложений по людям, лотам и периодам. Приложение устанавливается на телефон или компьютер и работает офлайн после первого открытия.

[Открыть приложение](https://tpskym.github.io/lot-ledger-pwa/)

## Возможности

- Люди, лоты и последовательные периоды с индивидуальными ставками.
- Пополнения, выводы и перенос результата в следующий этап.
- Итого вложено, сумма на конец и сумма процентов для портфеля и каждого участника.
- Режимы «Текущие» и «С планами»; начисления по месяцу окончания этапа.
- Подсказка о будущих этапах над кнопкой «Новый период»: лоты, даты и переход к истории периодов.
- История изменений, восстановление прежнего состояния, текстовые отчёты.
- Экспорт и восстановление JSON-копии вместе с историей.

## Начало работы

Публичная версия запускается с пустой базой. В разделе «Люди» добавьте участников. В «Лоты и периоды» создайте лот и первый период, введите начальные суммы, пополнения и ставку за весь период. Для следующего этапа используйте «Следующий период»: итог предыдущего переносится автоматически.

Чтобы перенести существующий учёт, в прежнем приложении откройте «Мои данные» → «Скачать JSON-копию». Затем в новой версии выберите «Мои данные» → «Выбрать JSON-файл» → «Восстановить». Адреса сайтов и браузеры хранят данные отдельно; перенос выполняется через копию.

## Расчёты

Для каждой строки участника:

```text
Итого в периоде = накоплено + добавлено − выведено
На конец = округлить вниз до целого рубля(итого × (1 + ставка / 100))
Проценты за период = на конец − итого
```

Округление выполняется отдельно для каждого человека, затем суммы складываются. Ставка относится ко всему периоду; по умолчанию предлагаются 8% за два календарных месяца.

«Итого вложено» — начальные суммы каждого лота, учтённые один раз, плюс все новые пополнения. Переносы между этапами повторно не прибавляются. «Сумма на конец» — итог выбранного этапа каждого лота. «Сумма процентов» в сводке — сумма на конец минус итого вложено. При выводах эта разница уменьшается на выведенные средства; отдельная таблица начислений показывает именно проценты по периодам.

«Текущие» выбирает последний начавшийся этап каждого лота на текущую дату по Москве. «С планами» выбирает последний записанный этап, включая будущий. Новые планы автоматически не создаются. Проценты текущего или будущего этапа рассчитаны на его окончание. В таблице месяцев начисления относятся к месяцу окончания этапа.

## Хранение данных

Все записи и история сохраняются в IndexedDB на устройстве. Данные не отправляются на GitHub и не синхронизируются между устройствами. Исходные таблицы приложение не изменяет. В репозитории нет личных расчётов: `dist/seed.json` содержит пустое состояние.

Регулярно сохраняйте JSON-копию: очистка данных сайта или удаление браузера могут удалить локальную базу. Резервные копии содержат ваши данные; храните их отдельно от публичного репозитория.

## Установка PWA

Откройте опубликованный сайт с интернетом, затем:

- iPhone/iPad: Safari → «Поделиться» → «На экран Домой».
- Android/компьютер: меню Chrome или Edge → «Установить приложение».
- Mac: Safari → «Файл» → «Добавить в Dock».

Первое открытие загружает файлы в офлайн-кэш. В Safari установленная версия может иметь отдельное хранилище; при необходимости перенесите JSON-копию.

## Локальный запуск

Нужен Node.js 22 или новее. Внешних зависимостей и сборки нет.

```sh
npm test
npm start
```

Откройте `http://127.0.0.1:4173/lot-ledger-pwa/`. Сервер использует тот же путь подпапки, что и GitHub Pages. Файлы нельзя запускать через `file://`: для модулей и service worker нужен HTTP на localhost или HTTPS.

## GitHub Pages

В настройках репозитория выберите **Settings → Pages → Build and deployment → Source → GitHub Actions**. Workflow `.github/workflows/pages.yml` проверит расчёты и PWA, затем опубликует каталог `dist`. Каждый push в `main` обновляет сайт. Можно запустить workflow вручную через вкладку Actions.

Манифест, иконки и service worker используют относительные пути и поддерживают адрес вида `https://USERNAME.github.io/lot-ledger-pwa/`. При изменении файлов приложения увеличивайте версию кэша в `dist/sw.js`, чтобы новая версия целиком обновила офлайн-файлы.

См. [документацию GitHub Pages для workflows](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).

## Структура

```text

tests/         проверки на искусственных данных
scripts/       локальный сервер
.github/       проверка и публикация через GitHub Actions
```
